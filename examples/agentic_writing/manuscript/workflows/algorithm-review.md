# Review Algorithms

Read the [review contract](review.md), target algorithm description or
pseudocode, definitions of inputs and outputs, the
[notation register](../notation.md), stated assumptions, relevant implementation, and supplied complexity analysis or
experiment records.

Check that inputs, outputs, state changes, termination conditions, and edge
cases are specified; that the prose, pseudocode, and implementation agree; and
that stated correctness or complexity claims have the required assumptions and
support. Identify ambiguities that would prevent independent implementation or
evaluation.

Return read-only findings in the shared format. Do not invent invariants, proof
steps, complexity bounds, benchmarks, or implementation behavior. Report when a
claim needs a proof, code inspection, experiment, or domain-expert decision.
